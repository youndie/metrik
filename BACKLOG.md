# metrik — бэклог

Лёгкий мониторинг Ktor-сервисов: плагин-агент, нативный сервер с SQLite, дашборд на Compose Wasm.
Архитектурные решения и обоснования — [docs/research/research-architecture.md](docs/research/research-architecture.md).
Читать перед тем, как брать любую задачу.

**Статус: M0–M7 закрыты.** Провод, агент, приём и хранение, API чтения, дашборд, алертинг и
эксплуатация написаны и покрыты тестами (151 тест, из них общий код прогоняется на JVM, native и
wasm). Сквозная проверка сделана на живом нативном бинаре: датаграмма → SQLite → HTTP API.

Осталось: **M-74 (лицензия)** — ждёт выбора владельца. Плюс список сознательно отложенного в конце
файла.

## M1 — протокол и общий код ✅

- [x] **M-10** `:shared`: модель `Frame`/`RouteSeries`/`SystemSnapshot`/`SlowSample` по
      [protocol-ingest](docs/api/protocol-ingest.md), `ignoreUnknownKeys = true`; кодирование
      статуса (`encodeStatus`, `statusClassOf`, `isServerError`).
- [x] **M-11** Кодек гистограммы: `durationToBucket`, границы бакетов, `percentileMs` с
      интерполяцией, сложение гистограмм, разреженная сериализация.
- [x] **M-12** Нарезка окна на пакеты ≤ 1200 байт (`splitWindow`), включая раскладку
      «системный срез в `q = 0`, сэмплы в последнем».

28 тестов, зелёные и на JVM, и на macosArm64 (`:shared:jvmTest`, `:shared:macosArm64Test`).
Ключевой из них — `percentile should stay within the documented error bound`: он проверяет
обещание доки (погрешность ≤ 20 %) на 10 000 сэмплов, а не текущую реализацию.

Серия, не влезающая в пакет в одиночку, не выбрасывается и не режется: пакет уходит как есть,
а `WindowSplit.oversized` даёт агенту повод это заметить. Молча терять данные в системе, которая
существует ради наблюдаемости, нельзя.

## M3 — сервер: приём и хранение ✅

- [x] **M-30** Ktor CIO native, конфиг из env, открытие базы и миграции до старта движка.
- [x] **M-31** Схема SQLite + миграции (`PRAGMA user_version`).

- [x] **M-33** Детект расхождений: дырки в `w` (счётчик пропущенных окон), расписки пакетов

- [x] **M-36** Слияние инстансов на записи (read-modify-write в той же транзакции) +
      идемпотентность по `(s, i, t, q)`, с тестом на повторный пакет.
- [x] **M-37** Отметки деплоя: смена `rel` → строка в `deploys`.
- [x] **M-34** Внутренние счётчики ingest + `/api/self`.
- [x] **M-35** Нагрузочная проверка: 500 окон (50 сервисов × 10 инстансов — минутный объём)
      принимаются за **0,74 с**, то есть на приём уходит около процента бюджета окна.

15 тестов на nativeTest, включая настоящий round-trip через UDP-сокет: датаграмма уходит в
приёмник и доезжает до строки в базе.

**Флаг `partial` в схеме не понадобился.** Расписки в `window_receipts` хранят `packet_count`, так
что неполнота окна вычисляется при чтении — держать в строке производное значение, которое ещё и
меняется задним числом (пакет мог доехать позже), значило бы иметь два источника правды.

## M5 — дашборд ✅

- [x] **M-50** Compose SPA (`:composeApp`, wasm + desktop) + `deploy/web.Dockerfile` с nginx,
      ktor-client к `/api` (js-движок на wasm, CIO на desktop). Опрос раз в 30 секунд: окно
      минутное, real-time тут ничего не добавит.
- [x] **M-51** Экраны: обзор со списком сервисов и активными алертами, сервис с вкладками
      «Графики / Маршруты / Медленные / Система», отметки деплоев на всех графиках.
- [x] **M-52** Честность отображения: `partial`-точки рвут линию (`toChart` отдаёт `null`),
      перцентили подписаны как приблизительные, «нет данных» вместо нулей, у нативных сервисов
      подпись «RSS», а не «heap», часовой шаг вместо минутного объявляется текстом.

**Сквозная проверка на живом бинаре:** датаграмма → UDP-приёмник → SQLite → HTTP API. Реальные
ответы: `errorRate 0.0625` при 8 ошибках из 128, `p95 ≈ 85 мс`, отметка деплоя `1.4.212`,
медленный сэмпл 8123 мс, `401` без заголовка прокси.

### Хвост от макета: чего не хватило контракта

Нарисовано в макете, но не реализуемо на текущем API — каждый пункт ждёт серверной части:

- [ ] **M-81** Кнопка «Отправить тестовое» и «Заглушить/mute на час» на экране алертов.
      Эндпоинтов нет: в контракте единственная мутация — `PUT` порогов. Нужны
      `POST /api/admin/alerts/test` и приглушение правила с TTL (плюс поле в `alert_states`).
- [ ] **M-82** Редактирование порогов прямо в панели «Пороги». Сервер это умеет
      (`PUT /api/admin/services/{id}/alerts`), UI пока только читает — нужна форма с валидацией
      и понятным поведением при отказе.
- [ ] **M-83** Абсолютное время в списках («12:41», «сегодня 09:14») вместо относительного.
      В `commonMain` нет работы с датами и часовыми поясами, а считать по UTC и выдавать за
      локальное время — ровно тот сорт вранья, который продукт запрещает себе в цифрах.
      Нужна `kotlinx-datetime` и решение, чей часовой пояс показывать.
- [x] **M-84** Селектор диапазона на «Обзоре» работает: `/api/services` принимает `from`/`to`
      (дефолт — последние пять минут), клиент передаёт выбранный период и пересчитывает и карточки,
      и спарклайны. Переключатель, который ничего не меняет, врёт не хуже неправильной цифры.
- [ ] **M-85** Период на вкладке «Медленные»: сервер всегда отдаёт последние 24 часа.
- [x] **M-86** Мобильная раскладка по трём кадрам макета: ниже 760dp рельс уезжает в нижнюю
      навигацию, карточки в одну колонку. Порог по ширине окна, а не по платформе — дашборд
      открывают и в узком окне на десктопе.
- [ ] **M-89** Маршруты, «Медленные» и «Система» на узком экране используют десктопные композаблы:
      таблица маршрутов в шесть колонок на 390dp тесновата. В макете отдельных мобильных кадров для
      них нет — нужен дизайн, а не догадка.
- [ ] **M-88** Шрифты макета (Roboto Flex с осью `opsz`, Roboto Mono). Нужны файлы шрифтов в
      compose-ресурсах; сейчас системный шрифт и `FontFamily.Monospace`.

## Найденные при эксплуатации

- [x] **M-90** `SelectorManager` занимал воркер `Dispatchers.Default`, и на узле с двумя ядрами
      три селектора (приёмник, отправитель агента, движок Ktor) не оставляли никого, кто возобновит
      корутину по таймеру: `delay` не срабатывал во всём процессе, датаграммы не принимались.
      Локализовано минимальной нативной программой в кластере (1 селектор — тикает, 2 — нет),
      разбор в research §1.5. Селекторы переведены на собственные потоки.

## Отложено сознательно

* **Бинарный кодек** вместо JSON — когда появится сервис, которому 1200 байт на пакет мало
  (research §Р3).
* **HTTP-фолбэк транспорта** для агентов вне кластера (research, открытый вопрос 2).
* **SSE/WebSocket real-time** — минутное окно делает это бессмысленным (research §Р6);
  нативные артефакты `ktor-server-sse` есть, дверь открыта.
* **Пользовательские метрики** (`counter("orders")`) — не в «глупом» агенте v1.
* **Трейсинг и correlation id** — другой продукт.
* **Мультитенантность** — решено, что её нет: одна инсталляция = одна команда (research §Р8).
  Нужна изоляция — поднимается вторая инсталляция.
