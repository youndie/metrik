# metrik — бэклог

Лёгкий мониторинг Ktor-сервисов: плагин-агент, нативный сервер с SQLite, дашборд на Compose Wasm.
Архитектурные решения и обоснования — [docs/research/research-architecture.md](docs/research/research-architecture.md).
Читать перед тем, как брать любую задачу.

**Статус: M0–M9 закрыты.** Провод, агент, приём и хранение, API чтения, дашборд, алертинг и
эксплуатация написаны и покрыты тестами (151 тест, из них общий код прогоняется на JVM, native и
wasm). Сквозная проверка сделана на живом нативном бинаре: датаграмма → SQLite → HTTP API.

Дизайн по макету «Metrik Expressive» реализован, лицензия выбрана (MIT), дашборд переразложен по
слоям (Clean/MVVM, Navigation 3, типизированный контракт). Открыт один пункт — **M-96**, техдолг
по навигации; остальное в конце файла, в списке сознательно отложенного.

### Хвост от макета: чего не хватило контракта

Нарисовано в макете, но не реализуемо на текущем API — каждый пункт ждёт серверной части:

- [x] **M-81** «Отправить тестовое» (`POST /api/admin/alerts/test`, честный `delivered: false`,
      если Telegram не настроен) и заглушение правила на срок (`PUT`/`DELETE …/alerts/{rule}/mute`,
      отдельная таблица `alert_mutes`). Заглушение глушит только доставку — правило продолжает
      гореть в UI, иначе «заглушил» означало бы «перестань замечать».
- [x] **M-82** Редактирование порогов в панели «Пороги»: форма с валидацией (пороги ≥ 0,
      окон ≥ 1), видимая ошибка при отказе сервера, метка «унаследовано / переопределено».
- [x] **M-83** Абсолютное время в списках и истории через `kotlinx-datetime` в зоне пользователя
      (`TimeZone.currentSystemDefault()`). Относительное осталось там, где оно честнее:
      «обновлено N с назад» и «горит N мин».
- [x] **M-84** Селектор диапазона на «Обзоре» работает: `/api/services` принимает `from`/`to`

- [x] **M-85** Период на «Медленных»: `/slow` принимает `from`/`to`, клиент передаёт выбранный

- [x] **M-86** Мобильная раскладка по трём кадрам макета: ниже 760dp рельс уезжает в нижнюю

## Найденные при эксплуатации

- [x] **M-90** `SelectorManager` занимал воркер `Dispatchers.Default`, и на узле с двумя ядрами
      три селектора (приёмник, отправитель агента, движок Ktor) не оставляли никого, кто возобновит
      корутину по таймеру: `delay` не срабатывал во всём процессе, датаграммы не принимались.
      Локализовано минимальной нативной программой в кластере (1 селектор — тикает, 2 — нет),
      разбор в research §1.5. Селекторы переведены на собственные потоки.

- [x] **M-94** Агент на нативных таргетах молчал всегда: `InetSocketAddress` на Kotlin/Native не
      разрешает доменное имя, `connect` падал с EINVAL, а агент по контракту глотает ошибки
      отправки — снаружи это неотличимо от исправного. Единственный работавший нативный агент —
      самонаблюдение metrik, у него endpoint `127.0.0.1`. Разбор в research §1.6; имя резолвится
      через `getaddrinfo`, тесты открывают настоящий сокет, включая доменный случай.

- [x] **M-95** Переключение сервиса в рельсе меняло подсветку, но не контент: записи стека
      Navigation 3 делят `ViewModelStore` хоста, и `koinViewModel` отдавал ViewModel,
      созданный под предыдущий сервис. `serviceId` переведён из параметра конструктора в
      состояние — см. M-96, там же и остаток долга.

- [ ] **M-96** Вернуться к `ViewModelStoreNavEntryDecorator`, когда navigation3 подрастёт.

      Штатное решение проблемы из M-95 — свой `ViewModelStore` на каждую запись стека. Оно
      требует ещё `SavedStateNavEntryDecorator`, которого в `navigation3-runtime:1.1.1` нет:
      `lifecycle-viewmodel-navigation3:2.10.0` падает на старте с
      «requires adding the SavedStateNavEntryDecorator». Апгрейд навигации и lifecycle ради
      одного экрана не окупился, поэтому взят обходной путь.

      **Почему это долг, а не решённый вопрос:** обход работает ровно потому, что экран с
      параметром в маршруте у нас один. Второй такой экран наступит на те же грабли, и симптом
      будет тот же — «подсветка меняется, контент нет», то есть тихо неверные данные, а не
      падение. Брать, когда в navigation3-runtime появится `SavedStateNavEntryDecorator` —
      или раньше, если появляется второй параметризованный маршрут.

## Отложено сознательно

* **Бинарный кодек** вместо JSON — когда появится сервис, которому 1200 байт на пакет мало
  (research §Р3).
* **HTTP-фолбэк транспорта** для агентов вне кластера (research, открытый вопрос 2).
* **SSE/WebSocket real-time** — минутное окно делает это бессмысленным (research §Р6);
  нативные артефакты `ktor-server-sse` есть, дверь открыта.
