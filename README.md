# metrik

Лёгкий мониторинг Ktor-сервисов: один плагин в сервисе, один бинарь на сервере, один файл SQLite.

Ниша — между «логов пока хватает» и «поднимаем Prometheus + Grafana + Alertmanager». metrik
отвечает на четыре вопроса: сколько запросов, сколько ошибок, насколько медленно, не кончается ли
память — и пишет в Telegram, когда с ответами что-то не так.

```kotlin
install(Metrik) {
    service = "orders-api"
    apiKey = System.getenv("METRIK_KEY")
    endpoint = "metrik-server:9999"
    release = System.getenv("APP_VERSION")
}
```

Регистрировать сервис не нужно: ключ один на инсталляцию, сервис заводится сам при первом пакете.

## Из чего состоит

| Компонент | Что это | Стек |
|---|---|---|
| `metrik-agent` | Ktor-плагин: меряет, агрегирует в минутное окно, шлёт по UDP | Kotlin Multiplatform (JVM + Native) |
| `metrik-server` | принимает, хранит, считает алерты, отдаёт JSON | Kotlin/Native, Ktor CIO, SQLite (sqlx4k) |
| `metrik-web` | дашборд | Compose Multiplatform: Wasm в проде, desktop для отладки; nginx |

Ключевое решение: **агрегирует агент, а не сервер.** Сервис на 1000 rps шлёт один-два пакета в
минуту вместо 60 000 датаграмм. Цена — приблизительные перцентили (±20 %), чего достаточно для
трендов и алертов и недостаточно для формального SLA-репортинга. Обоснование и остальные решения —
[docs/research/research-architecture.md](docs/research/research-architecture.md).

## Модель установки

Одна инсталляция принадлежит одной команде и мониторит сколько угодно сервисов, у каждого — сколько
угодно инстансов. Мультитенантности внутри нет: нужна изоляция от другой команды или другого
контура (test/prod) — поднимается вторая инсталляция, это один бинарь и один файл.

Собственного логина у metrik нет: UI закрывается reverse proxy (oauth2-proxy, Traefik ForwardAuth,
nginx auth_request), сервер доверяет заголовкам `X-Auth-Request-User` / `X-Auth-Request-Email` —
как в katcher. **Без прокси metrik ставить нельзя**, дашборд будет открыт всем, кто дотянулся до порта.

## Статус

Каркас собран (M0): четыре модуля, сборка под jvm / linuxX64 / linuxArm64 / macosArm64 / wasm,
CI, нативный бинарь с `/health`. Содержательного кода ещё нет — дальше M1 (протокол и кодек
гистограммы), порядок работ в [BACKLOG.md](BACKLOG.md).

Проект открытый, как [katcher](https://github.com/youndie/katcher). Лицензия ещё не выбрана —
до первой публикации образа это надо закрыть (M-74), иначе формально код неиспользуем.
