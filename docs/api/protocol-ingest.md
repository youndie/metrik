# protocol-ingest — провод между агентом и сервером

Транспорт: **UDP**, порт по умолчанию `9999`. Тело — JSON (UTF-8), сериализация
`kotlinx.serialization`. Один датаграмм = один самодостаточный `Frame`.

Обоснование выбора (UDP, JSON, предагрегация) — [research-architecture](../research/research-architecture.md) §Р1–Р3.

## Инварианты

1. **Пакет ≤ 1200 байт.** Не API-шный лимит Ktor (`MAX_DATAGRAM_SIZE`), а MTU: фрагментированная
   датаграмма теряется целиком. Агент режет окно на несколько пакетов, если не влезает.
2. **Пакет самодостаточен.** Потеря любого пакета не мешает разобрать остальные.
3. **Fire-and-forget.** Сервер не отвечает. Агент никогда не ждёт и никогда не ретраит.
4. **Ключи короткие.** Поля в один-два символа: при 1200 байтах на пакет длина ключей —
   это количество серий, которое влезет.

## Frame

```json
{
  "v": 1,
  "k": "mk_live_9f3a…",
  "s": "orders-api",
  "i": "orders-api-7d9f8-x2k1",
  "rel": "1.4.212",
  "t": 1754049600000,
  "d": 60000,
  "w": 12043,
  "q": 0,
  "n": 2,
  "r": [ /* RouteSeries[] */ ],
  "y": { /* SystemSnapshot, только при q = 0 */ },
  "x": [ /* SlowSample[], только в последнем пакете */ ]
}
```

| Поле | Тип | Смысл |
|---|---|---|
| `v` | Int | версия протокола, сейчас `1`. Сервер молча дропает незнакомые версии и считает их в счётчик |
| `k` | String | ingest-key **инсталляции** (один на всю установку metrik, не на сервис) |
| `s` | String | логическое имя сервиса (одно на все инстансы). Неизвестное имя → сервис создаётся автоматически |
| `i` | String | идентификатор инстанса: hostname/pod-name + суффикс запуска |
| `rel` | String? | версия релиза (`1.4.212`, тег образа, git sha). Только в пакете `q = 0`. Смена значения = деплой, сервер отмечает его на графиках |
| `t` | Long | начало окна, epoch ms, кратно `d` |
| `d` | Int | длительность окна в ms (дефолт `60000`) |
| `w` | Long | монотонный номер окна с момента старта инстанса — дырки = потерянные окна |
| `q` | Int | номер пакета внутри окна, с нуля |
| `n` | Int | всего пакетов в этом окне |
| `r` | RouteSeries[] | серии по маршрутам |
| `y` | SystemSnapshot? | системный срез; присылается один раз за окно, в пакете `q = 0` |
| `x` | SlowSample[]? | самые медленные запросы окна; в пакете `q = n - 1` |

`w` и пара `q`/`n` — единственный способ отличить «сервис молчал» от «пакеты не долетели»
(Риск 2 в research). Сервер обязан их использовать, а не игнорировать.

## RouteSeries

```json
{"m": "GET", "p": "/shops/{shopId}/products/{id}", "c": 2,
 "n": 1043, "s": 18234, "x": 812,
 "b": [[14,5],[15,120],[16,600],[17,300],[18,18]]}
```

| Поле | Тип | Смысл |
|---|---|---|
| `m` | String | HTTP-метод |
| `p` | String | **шаблон** маршрута из `RoutingCall.route`, не сырой путь. `<unmatched>` — если маршрут не сматчился, `<other>` — если серия вытеснена лимитом кардинальности |
| `c` | Int | статус, кодирование см. ниже |
| `n` | Int | количество запросов |
| `s` | Long | сумма длительностей, ms (для среднего) |
| `x` | Int | максимум, ms |
| `b` | [[Int, Int]] | разреженная гистограмма: пары `[индекс бакета, количество]`, только непустые |

Ключ серии — `(m, p, c)`. Пары `(m, p)` с разными статусами — разные серии; так error rate
считается без отдельного счётчика.

### Кодирование статуса (поле `c`)

```
status = 0            → c = 0    // ответа не было: исключение до отправки, обрыв соединения
100 ≤ status < 400    → c = 1|2|3   // класс: 1xx, 2xx, 3xx
400 ≤ status ≤ 599    → c = status  // точный код: 404, 401, 500, 503
status > 599          → c = 5      // нестандартные коды схлопываются в класс
```

Значения `0…5` — класс, значения `400…599` — точный код; спутать нельзя, разбор однозначен.

Осознанный размен: точные коды умножают число серий (успешный трафик обычно однороден, ошибочный —
нет), зато `401` отличается от `404`, а `500` от `503` — то есть «сломалась авторизация» отличается
от «клиент стучится не туда», а «упало приложение» от «упала зависимость». Ради этих различий на
алерты и смотрят, поэтому цена оправдана; на успешном трафике она нулевая.

### Бакеты гистограммы

```
duration < 1 ms          → индекс 0
1 ms ≤ duration ≤ 10 s   → индекс = ceil(ln(ms) / ln(1.2))     // 1…51
duration > 10 s          → индекс 52 (overflow)
```

γ = 1.2 ⇒ ширина бакета 20 % ⇒ **погрешность перцентиля ≤ 20 %** (с линейной интерполяцией внутри
бакета — меньше). Это осознанный размен, см. research §Р2: metrik годится для трендов и алертов и
не годится для формального SLA-репортинга.

Кодек (кодирование дельты в индекс, декодирование индекса в границы, расчёт перцентиля по
разреженным парам) живёт в `:shared` и покрыт тестами — общий код агента и сервера, расходиться
им нельзя.

## SystemSnapshot

```json
{"hu": 268435456, "hm": 1073741824, "cp": 340, "th": 42, "up": 864000, "gc": {"c": 12, "t": 87}}
```

| Поле | Тип | Смысл |
|---|---|---|
| `hu` | Long | использовано heap (на нативе — RSS), байт |
| `hm` | Long? | максимум heap, байт. У нативного процесса такого понятия нет — туда идёт лимит cgroup, если читается, иначе поля нет |
| `cp` | Int | CPU процесса за окно, промилле от одного ядра (`340` = 34 % одного ядра) |
| `th` | Int | число тредов |
| `up` | Long | uptime процесса, секунды |
| `gc` | Object? | **опционально**: `c` — число сборок за окно, `t` — суммарное время, ms. Присутствует только там, где доступен JMX/рантайм-API (см. [feature-system-metrics](../features/feature-system-metrics.md)) |

Отсутствие `gc` — нормальная ситуация, а не ошибка. UI показывает «нет данных», не ноль.

## SlowSample

```json
{"m": "POST", "p": "/orders", "c": 503, "ms": 8123, "t": 1754049612345}
```

Top-N (дефолт 5) самых медленных **завершённых** запросов окна. Сознательно не передаются: тело,
заголовки, query string, сырой путь с идентификаторами — metrik не должен становиться местом,
где случайно оседают персональные данные.

## Поведение сервера при приёме

| Ситуация | Поведение |
|---|---|
| `v` неизвестна | дроп, инкремент счётчика `ingest_unknown_version` |
| `k` не совпадает с ingest-key инсталляции | дроп, счётчик `ingest_bad_key` |
| JSON не парсится | дроп, счётчик `ingest_malformed` |
| `s` не встречался раньше | сервис создаётся автоматически (ключ один на инсталляцию, регистрировать нечего) |
| `rel` отличается от последнего известного для инстанса | запись в `deploys`, на графиках появляется отметка деплоя |
| `t` отличается от времени сервера более чем на 5 минут | дроп окна, инстанс помечается `clock_skew` |
| пришли не все `n` пакетов окна | окно сохраняется как есть с флагом `partial` |
| дырка в `w` | окна между отмечаются как пропущенные (в UI — разрыв линии, не ноль) |
| дубль `(s, i, t, q)` | идемпотентно игнорируется |

Окна разных инстансов за одну и ту же минуту **сливаются на записи** в одну строку: счётчики
складываются, гистограммы складываются побакетно, максимум берётся максимумом (см.
[metrik-server](../services/metrik-server.md), «Схема данных»). Поэтому дубль пакета обязан быть
именно идемпотентным — повторное слияние испортило бы цифры молча.

Ответов нет ни в одном из случаев — счётчики видны в самом metrik.

## Совместимость

Версия `v` поднимается только на ломающих изменениях. Аддитивные поля агент может слать сразу:
сервер обязан игнорировать незнакомые ключи (`ignoreUnknownKeys = true`), это часть контракта.
